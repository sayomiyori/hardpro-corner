## Проверка 28 ноября

На сервере три RTX 3090. GPU 0 обслуживает 14B, GPU 1 — 27B, GPU 2 — 3D-фабрику. Обе модели ответили после восстановления. [Замеры одного процесса Flash Next на трёх GPU](docs/three-3090-flash-next.md)

После обновления прошли 100 контрольных вопросов через сервис. [Покупательский чат](docs/storefront-widget-cards-2026-11-25.md) · [Защита](docs/storefront-security-2026-11-25.md)

## Снимок сервера 24 ноября

Ubuntu 24.04.5 LTS, ядро 6.8, Python 3.12, драйвер NVIDIA 580.178.04, две RTX 3090 по 24 ГиБ. Раздел моделей ext4 смонтирован в `/srv/models`. Занято 249 ГиБ, доступно около 3,5 ТиБ.

| Медиа и Flowise | Медиа-модель ответила на `/v1/models` и работала на CPU. Flowise слушал loopback на `8768` и вернул 200 на `/api/v1/ping`. В журнале запуска Flowise есть предупреждение об отсутствующей зависимости `@smithy/eventstream-codec`. Потоки не проверялись. |
| Роутер и 27B | Юнит роутера выключен. В панели сохранён 27B для GPU 1 с окном 131 072, K `q8_0`, V `q4_0`, MTP `n=3` и батчем `512/256`. При внедрении контрольный запуск прошёл. Резервный файл содержал выгрузку от 18 ноября, 12:05 МСК. Чтение регистра и контрольный менеджерский диалог в этой сверке не выполнялись. |

## Что подтвердили предыдущими тестами

- Менеджер при сбое источника отвечал по снимку с датой. После контрольной перезагрузки сервер отвечал через 30–40 секунд. [Резервный режим 1С](docs/manager-link-recovery.md)
- На 27B выбрали MTP `n=3` по сравнению с обычным декодом, отдельно проверили потоковую выдачу, tool calls и длинный вход. [Отчёт о замерах](docs/llm-speed-27b.md)
- Для поиска инструкций проверили BM25, MiniLM и гибридное ранжирование. Подключение этого пилота к двум чатам требует отдельной приёмки. [Гибридный поиск](docs/knowledge-retrieval-pilot.md)
- Работоспособность OData подтверждается тестом с подставной 1С. У COM-моста свой набор инструментов. Проведение документов и восстановление всей цепочки после отключения питания требуют отдельной эксплуатационной проверки. [MCP для 1С](onec-mcp/README.md) · [Канал менеджера](docs/manager-link-recovery.md)
