# Утилиты LocalLLM

## Аппаратная сводка для SSH

На Linux команда `python3 hp-status` показывает процессор, память, накопители и отдельную карточку каждой NVIDIA GPU. Для определения датчиков используются hwmon, NVML и доступные системные утилиты. Если NVML недоступна, программа пробует nvidia-smi. Кеш в `$XDG_CACHE_HOME/hp-status` (по умолчанию `~/.cache/hp-status`) помогает заметить исчезнувшую карту.

~~~sh
python3 hp-status
python3 hp-status --full
python3 hp-status --temperatures
watch -n 2 ./hp-status --gpus
~~~

## Исторический профиль длинного контекста

[Drop-in для llama.cpp](context/30-long-context.conf) задаёт общий контекст 524 288 токенов, два параллельных слота и KV-кеш в ОЗУ. [Пресет](context/qwen38-long-context.ini) содержит две версии Qwen3.8-27B. Роутер держит одну модель в памяти. Публичное имя пресета позволяет хранить его рядом с текущим пресетом из каталога systemd.

Для воспроизведения на отдельном стенде поместите INI в каталог, указанный в `--models-preset`, и примените drop-in к пользовательскому юниту роутера. Проверьте через `systemctl --user cat ИМЯ_ЮНИТА`, какой ExecStart получается после всех drop-in. Модели доступны через список `/v1/models` после запуска роутера. Актуальные замеры отдельного профиля на трёх GPU приведены в [отчёте Flash Next](../docs/three-3090-flash-next.md).

## Фото, видео и голосовые в Open WebUI

[Фильтр HARD-PRO Media](media/openwebui_media.py) передаёт изображения локальной модели зрения и добавляет в запрос к текстовой модели описание вложений. Для видео он выбирает до шести кадров и извлекает речь с помощью faster-whisper. Для отдельного голосового сообщения берёт готовую расшифровку Open WebUI. Вложение по идентификатору доступно только пользователю, которому принадлежит загрузка.

Один запрос обрабатывает до четырёх изображений, одного видео длительностью до трёх минут и одного голосового. Лимит файла — 24 МиБ. Фильтр использует PyAV, Pillow, aiohttp и faster-whisper в окружении Open WebUI.

1. Проверьте пути к бинарному файлу llama.cpp, GGUF модели, проектору mmproj и локальным весам Whisper. [Пользовательский юнит модели зрения](media/hardpro-media-vision.service) запускает инференс на CPU и слушает loopback. Рабочий каталог юнита и каталог TMPDIR должны существовать.
2. Скопируйте [пример окружения](media/webui.env.example) в файл, указанный в [40-media.conf](media/40-media.conf). Подставьте адреса локальных API вашей установки. Фильтр обращается к сервису зрения по VISION_URL. Пример предполагает, что оба процесса работают в одном сетевом пространстве Linux.
3. Поместите юнит зрения в каталог пользовательских юнитов systemd, а 40-media.conf — в каталог drop-in **службы Open WebUI**. Перечитайте конфигурацию командой `systemctl --user daemon-reload` и запустите сервис зрения. Для работающего Open WebUI переменные окружения применятся при следующем перезапуске.
4. Загрузите Python-файл в раздел функций Open WebUI и включите фильтр для нужных моделей из LOCAL_MODELS. Проверить результат можно фотографией известного предмета и коротким роликом с речью. Вопрос по вложению должен учитывать его содержимое.
