# Воспроизведение замеров MTP на 27B

[Статья о замерах](../../docs/llm-speed-27b.md) · [Контекст 128K и новый сценарий](../../docs/long-context-27b.md) · [Службы systemd](../README.md) · [Текущий статус](../../STATUS.md)

Комплект для измеряемого разгона llama.cpp-сервера 27B: повторяемый набор
запросов, скрипты включения speculative decoding и отката, агрегатор результатов.

## Модель и точка входа

- Файл: `/srv/models/weights/coding/Huihui-Qwen3.8-27B-abliterated-Q5_K.gguf` (19,5 ГБ),
  архитектура GGUF `qwen35`, гибрид: gated-delta-слои + полный attention каждый 4-й слой
  (`full_attention_interval = 4`), 4 KV-головы по 256 dim.
- В весах есть MTP-голова: `qwen35.nextn_predict_layers = 1`, тензоры `blk.64.nextn.*`.
  Проверено чтением метаданных GGUF — вторую копию модели для этого не грузили.
- Сборка llama.cpp: `b12375` / commit `9d25e0014` (`llama serve`, единый бинарник).
- Сервис: `hardpro-abliterated-27b`, порт 8084, каталог моделей `~/hardpro/models/profiles.json`,
  роль одна карта — одна модель (GPU 1, `CUDA_VISIBLE_DEVICES` от переключателя).

## Что даёт выигрыш

Три рычага проверены измерениями (одинаковый набор, sampling зафиксирован):

1. **MTP speculative decoding** (`--spec-type draft-mtp --spec-draft-n-max 2`) —
   черновые токены генерирует MTP-голова из самих весов, дополнительно ничего
   не скачивается. Декод ускоряется примерно в 1,8–2,2 раза, prefill и TTFT не меняются.
2. **Flash Attention + KV q8_0/q8_0** — уже работали в baseline через явные флаги;
   повторного выигрыша от них ждать не стоит, включать для сверки смысла нет.
3. **Prefix cache** — при повторных запросах с общим началом TTFT падает
   с ~30 с до ~0,2 с; работает и между разными промптами с общим префиксом.

### Замеры 21 и 24 ноября 2026 (медианы, GPU RTX 3090, threads 16, parallel 1, контекст 65536)

| случай | вход | baseline decode | mtp2 (n=2) | mtp3 (n=3, выбран) |
| --- | --- | --- | --- | --- |
| short_code (256 out) | ~223 | 38,5 т/с | 65,1 т/с | **70,2 т/с** |
| short_tool (tool calls) | ~390 | 38,3 т/с | 72,6 т/с | **83,9 т/с** |
| long32, fresh | 33 274 | 32,3 т/с | 56,7 т/с | **64,8 т/с** |
| long60, fresh | 62 103 | 28,5 т/с | 49,4 т/с | **52,3 т/с** |

Итоговая прибавка к baseline: +82…+119 % на декоде. TTFT (prefill ~1170 т/с на 33K,
~1010 т/с на 62K свежих токенов): 28,5–33,9 с на свежем вводе, 0,13–0,26 с при
повторном префиксе; полностью холодный префилл 62K — ~61 с. Пиковая VRAM:
20,6 ГиБ baseline, 21,8 ГиБ с MTP n=3 (запас ~2,2 ГиБ на карте 24 ГиБ).

Счётчики MTP из журнала сервера: n=2 — acceptance 0,66 (113/171), mean len 2,31;
n=3 — 0,62 (249/400) и 0,55 (238/434), mean len 2,64–2,86. Режим выбран по
времени ответа, а не по acceptance.

Отдельные факторы, проверенные и отклонённые: `--ubatch-size 2048` даёт prefill
+3 % при пиковой VRAM +1 ГиБ (запас падает до ~1,2 ГиБ) — отклонено; KV-кэш
уже был q8_0/q8_0 в baseline. Проверены на финальной конфигурации: streaming,
tool calls, окно 65536 без усечения (33K и 62K входа), очередь при parallel=1,
совместная работа с менеджером 14B на GPU 0, сохранность профиля при
контрольной перезагрузке сервера. При сверке 24 ноября профиль был на месте, порт модели не отвечал. [Статус сервера](../../STATUS.md)

Ограничения эксперимента. `n_max = 4` не проверен; ngram-спекуляция для задач правки
кода не проверена; битовая идентичность ответов с MTP не гарантируется.

## Как воспроизвести

Запускайте в каталоге `systemd/tuning-27b` на выделенном стенде. Проверьте `/slots` перед перезапуском. Укажите свой каталог моделей, если он отличается от `~/hardpro/models/profiles.json`.

```bash
export HP_MODELS_FILE="$HOME/hardpro/models/profiles.json"
cp "$HP_MODELS_FILE" "$HP_MODELS_FILE.before-bench"
curl --fail http://127.0.0.1:8084/slots

bash exp_mtp.sh none
bash run_suite.sh baseline

bash exp_mtp.sh draft-mtp 3
bash run_suite.sh mtp3
python3 aggr.py

bash rollback.sh "$HP_MODELS_FILE.before-bench"
```

`exp_mtp.sh` перезаписывает `args` профиля `hardpro-abliterated-27b` в
`profiles.json` (n_ctx 65536 + spec-флаги), делает копию профиля рядом и
перезапускает сервис через штатный переключатель (`hp-model stop` + `launch`).
Проверьте настройки до прогона. При сравнении меняется глубина черновика, а порт, alias, шаблон, reasoning и KV-типы сохраняются. Если исходный стенд не отвечает, сначала восстановите запуск профиля.

## Граница применимости

- Флаги `--spec-type draft-mtp` существуют в этой сборке; для другой версии
  llama.cpp сверь `llama serve --help` — синтаксис спекулятивного декода менялся.
- MTP работает только когда в GGUF есть `nextn`-тензоры: имя файла не доказательство,
  проверяй метаданные (см. [gguf_dump](https://github.com/ggml-org/llama.cpp/blob/master/gguf-py/gguf/scripts/gguf_dump.py)).
- Замеры зависят от скважности запросов к другим сервисам; перед сравнением
  убедись, что 14B-менеджер на GPU 0 и остальные службы в том же режиме.
