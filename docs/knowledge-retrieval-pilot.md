# Гибридный поиск инструкций по экипировке

20 ноября 2026 года проверили локальный поиск по 14 источникам. Индекс содержит описания товаров, документы федераций и инструкции производителей. Результат поиска содержит заголовок, краткое содержание и ссылку. Цена, остаток и наличие вариантов проверяются по данным каталога, когда пилот подключат к боту.

## Что измерили

Сравнили BM25 с русским стеммингом, семантический поиск с многоязычной MiniLM и их объединение через Reciprocal Rank Fusion. Все три режима используют один корпус и Qdrant в памяти процесса. Режимы проверяли последовательно по три раза после прогрева. Замеры сделаны на Windows, Python 3.14, CPU AMD Ryzen 5 5600, по одному запросу. Время включает построение векторов запроса и поиск, загрузка модели и индексация выполнены заранее.

| Запросы | Режим | Нужный источник первый | Нужный источник в первых трёх | p95 |
| --- | --- | ---: | ---: | ---: |
| 21 открытый пример | BM25 | 15 | 17 | 0,59 мс |
| 21 открытый пример | MiniLM | 14 | 18 | 11,22 мс |
| 21 открытый пример | Гибридный | 17 | 20 | 17,98 мс |
| 22 вопроса из внутреннего чек-листа | BM25 | 18 | 21 | 0,37 мс |
| 22 вопроса из внутреннего чек-листа | MiniLM | 14 | 21 | 11,74 мс |
| 22 вопроса из внутреннего чек-листа | Гибридный | 20 | 22 | 11,61 мс |

Для каждого вопроса засчитывали появление одного подходящего источника. Два дополнительных открытых запроса с отсутствующими ключами темы во всех трёх режимах вернули пустой список. Внутренние вопросы выбраны из 100 по покрытию корпусом. Их формулировки хранятся в локальном рабочем наборе.

В открытом наборе гибридный поиск лучше находил источники по перефразированным вопросам. Вопросы о регламенте турнира и брекетах показывают, почему одного ранжирования мало. Например, слово ITF на карточке товара может вывести её выше регламента. После того как приложение определит задачу и федерацию, оно может ограничить поиск ключом темы. Для инструкции по подгонке важен точный ключ модели. Если для него нет документа, модуль возвращает пустой результат.

Эти цифры описывают поиск. Для оценки диалога нужны ответы модели, проверка ссылок и полный чек-лист по обоим ботам. Дальше имеет смысл подключить поиск к вопросам об инструкциях и подборе на изолированном стенде. Вызовы цены и остатка проходят через существующий каталог.

## Запуск

Из корня репозитория. Модели FastEmbed загрузятся при первом обращении. Папку кэша укажите на диске для рабочих данных.

```powershell
python -m pip install -r knowledge-pilot/requirements.txt
$ragCache = 'E:/Work/Temp/hardpro-rag-models'
python -X utf8 knowledge-pilot/retrieval.py --cache $ragCache benchmark
python -X utf8 knowledge-pilot/retrieval.py --cache $ragCache search 'Можно ли кипятить SISU 3D?' --scope sisu-3d
$env:FASTEMBED_CACHE_PATH = $ragCache
python -X utf8 -m unittest discover -s knowledge-pilot -v
```

У `search` по умолчанию включён гибридный режим. Сравнить выдачу можно с `--mode lexical` или `--mode dense`. Ключ для `--scope` берётся из проверенного контекста. Если модель капы или регламент остаются неясными, покупателю нужно задать уточняющий вопрос до выдачи инструкции. Выдача без фильтра показывает кандидатов на сверку.
