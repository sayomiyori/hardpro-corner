# Канал к 1С: ответы без доступа к базе и восстановление после отключения питания

[Документация](README.md) · [Текущий статус](../STATUS.md)

Каталог читает рабочую 1С. При сбое помощник может ответить по последнему доступному снимку и показать его дату. Обновление снимка при успешном чтении выполняется атомарно с интервалом не чаще пяти минут. Если пригодных данных нет, справочник остатков недоступен до восстановления источника.

## Слои и их поведение

| Слой | Пока всё работает | При отключении 1С или сервера 1С |
| --- | --- | --- |
| Qwen3-14B (vLLM) | отвечает за 0,1–0,5 с | не затрагивается: модель локальная |
| `hardpro-catalog` | читает 1С, сохраняет снимок | отвечает по снимку, помечает дату |
| Канал к 1С | SSH через промежуточный хост | `hardpro-link-guard.timer` проверяет раз в три минуты и перезапускает канал |
| Читатель 1С на стороне базы | держит сеанс COM | сторож `reader_watchdog.ps1` поднимает процесс и туннель |

Пример ответа при недоступной 1С и доступном снимке.

```
Рабочая 1С сейчас не отвечает, отвечаю по последней выгрузке на 24.11.2026 12:05 МСК.
Свежее наличие и брони не подтверждены.
```

Повторные вопросы в течение двух минут не ждут мёртвый канал: `hardpro-catalog` держит
паузу после сбоя. Замер на стенде: первый вопрос после простоя — 10,5 с, следующие — 0,09 с.

## Что поднимается само после перезагрузки сервера

Пользовательские службы запускаются через linger, без входа в систему:

- `hardpro-vllm` — модель; ждёт монтирования диска моделей (`RequiresMountsFor=/srv/models`),
  лимит перезапусков снят, `Restart=always`;
- `hardpro-catalog`, `hardpro-onec-link` — `Restart=always`: канал переподключается сам,
  если SSH умер молча;
- `hardpro-openwebui`, `hardpro-gateway`, `hardpro-trace`, `hardpro-hub`, `hardpro-agent`,
  `hardpro-widget`, `hardpro-models`;
- `hardpro-link-guard.timer` — сторож канала к 1С.

Проверка выполнена перезагрузкой сервера: через 30–40 секунд `/health` модели отвечает
200, менеджер отдаёт список вариантов по снимку, Open WebUI открывается. Этот прогон подтвердил восстановление Ubuntu и выдачу по снимку. При сверке 24 ноября таймер продолжал перезапускать канал. Свежего снимка не было, резервная выгрузка датирована 18 ноября. [Текущий статус](../STATUS.md)

## Что нужно один раз сделать на стороне 1С

1. BIOS или панель сервера: **Restore AC Power Loss = Power On**, иначе после отключения
   питания машина останется выключенной до нажатия кнопки.
2. Службы 1С и SQL — в автозапуске, это штатное поведение.
3. Зарегистрировать сторожа читателя через установщик из рабочей копии менеджера. Системная задача нужна, чтобы запуск не зависел от сеанса RDP.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install_reader_watchdog.ps1
```

Задача `HARD-PRO 1C reader watchdog` запускается при старте системы и каждые две минуты
проверяет порт читателя, поднимая процесс и обратный SSH-туннель. Журнал — `watchdog.log`
рядом со скриптом.

## Проверка канала

```bash
systemctl --user status hardpro-onec-link.service --no-pager
journalctl --user -u hardpro-catalog.service -n 40 --no-pager | grep -i 'канал рабочей 1С'
journalctl --user -u hardpro-link-guard.service --no-pager | tail
```

- `RemoteDisconnected` сразу после TLS-рукопожатия — читатель принял соединение, но не
  открыл сеанс к базе; проверяются права служебной учётки и журнал сторожа.
- `ConnectionRefusedError` — туннель есть, читателя нет: задача на стороне базы не запущена.
- `TimeoutError` — сеть или промежуточный хост; помогает перезапуск `hardpro-onec-link`.

Для сквозной проверки спросите в Open WebUI про известный вариант товара. Ответ с датой снимка подтверждает работу резервного режима. Для свежего остатка сверьте магазин, размер и момент чтения с регистром.
