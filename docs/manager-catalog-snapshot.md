# Локальная копия каталога чат-менеджера

20 ноября 2026 года. Изменение реализовано и проверено локально. Рабочий сервис использует предыдущую версию.

## Почему файл и индекс в памяти

В рабочем контуре чтение 22 496 строк справочника заняло 123,25 секунды. Читатель выполнил 72 последовательных запроса, ответ весил около 6 МБ. По уже загруженному индексу тот же вопрос вместе с разбором Qwen отработал за 0,48 секунды. Пауза возникала после истечения пятиминутного кеша, когда обновление справочника выполнялось внутри запроса менеджера.

В live-режиме сервис хранит рабочую копию в `~/.local/share/hardpro/catalog-web/data/catalog-snapshot.json`. На сервере этот каталог находится на NVMe. Файл содержит дату завершения чтения, коды, названия, артикулы, варианты и идентификаторы товаров и характеристик. Этого формата достаточно, чтобы после перезапуска восстановить существующий поисковый индекс `Catalog`. Остатки, цены, реквизиты и ключи доступа в файл не входят.

## Работа и сбои

- При запуске `hardpro-catalog` читает последнюю сохранённую копию и строит индекс в памяти. Фоновый поток начинает чтение 1С при запуске и повторяет его через 15 минут после каждого завершения. Один рабочий процесс сервиса запускает один поток обновления.
- Пока загружаются страницы, диалоги используют текущий индекс. После проверки корректности даты, полей, идентификаторов, отсутствия дублей и пустой выгрузки сервис записывает файл с правами владельца. Он сбрасывает содержимое на диск и атомарно заменяет рабочую копию файлом из того же каталога. После этого публикуется новый индекс. Сбой загрузки или сохранения оставляет последнюю успешную копию. В журнал попадают число строк после успешного обновления или тип ошибки.
- В ответе по справочнику указывается дата копии. Остатки и цены по-прежнему проверяются в рабочей 1С. Если сверка остатка прервётся, чат покажет выбранные товары и сообщит, что актуальное наличие подтвердить не удалось. Запросы живых данных всё равно зависят от времени ответа читателя 1С.
- При первом запуске нужна успешная полная выгрузка. До неё поиск возвращает 503 с сообщением о загрузке справочника. Существующий архив содержит 3 434 строки и давал 3 совпадения вместо 20 на контрольном вопросе. Его режим запускается отдельно при отсутствии `ONEC_READER_CONFIG`.

## Проверка

Локально пройдены тесты перезапуска при недоступной 1С, поиска во время обновления, отказа на следующей странице, отказа при дублировании строк и обработки испорченной копии. При недоступности остатков проверено, что ответ содержит выбранную позицию и сообщает о неизвестном наличии.

В отдельном прогоне API использовались 22 496 синтетических строк в 72 страницах, подменённый разбор запроса и зависшее чтение 1С. Запуск и восстановление индекса заняли 1,03 с, запрос после запуска — 0,026 с. Ответ содержал 20 совпадений. Проверены авторизация и потоковый ответ. Эти цифры характеризуют локальный API с подменённым разбором запроса.

Для приёмки на тестовом экземпляре с рабочим читателем дождаться полной копии, затем прервать доступ этого экземпляра к читателю. Проверить тот же вопрос через Open WebUI после перезапуска. Повторить с обрывом обновления на промежуточной странице и после восстановления связи. Цель по списку товаров — до двух секунд после готовности сервиса.

## Поиск на сайте

Покупательский бот использует опубликованные товары, цены и остатки самой витрины. На закрытом стенде 20 ноября 2026 года чтение выгрузки из 57 строк по действующему каналу заняло 1,32 с. Построение индекса заняло около 4 мс, поиск — около 2 мс. После истечения текущего восьмисекундного кеша чтение происходит в потоке первого запроса за новой копией.

Для следующей доработки стоит вынести обновление опубликованного каталога в фон и держать готовый индекс в памяти виджета. Сохранённая копия на диске позволит запустить поиск после перезапуска при недоступной витрине. Если обновление сорвалось, по копии можно вернуть карточку и варианты с датой данных. Цену и наличие стоит выводить только при подтверждённой свежести снимка витрины. После реализации сравнить холодный и повторный запросы и проверить, что скрытый товар исчезает после обновления, а просроченный остаток обозначен как неизвестный.
