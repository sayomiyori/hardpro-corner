# Доступ менеджера к рабочей «Рознице»

24 ноября 2026 года сверены метаданные и права из выгрузки «Розницы» 2.3.23.58.
Учётная запись `HP_Manager_Read` используется Windows-читателем. Внутренние запросы
выполняются через существующий канал с взаимной проверкой сертификатов.

## Товарный каталог

Назначьте служебной записи четыре штатные роли.

| Роль в «Рознице» | Что использует чат |
| --- | --- |
| Запуск внешнего соединения | Вход через COMConnector |
| Чтение информации по номенклатуре | Карточки, характеристики, упаковки, описания, виды номенклатуры |
| Чтение остатков товаров | Свободное количество по двум магазинам на основании регистра `ТоварыНаСкладах` |
| Чтение цен номенклатуры | Розничные цены по номенклатуре и характеристике |

Права на изменение данных в этих четырёх ролях не обнаружены. Каталожный запрос читает
розничный вид цены из настроенного справочника видов цен.

## Продажи, закупки и заказы

Для расширенного доступа заведите отдельную роль `HP_ЧтениеДанныхМенеджера`.
Включите право **Чтение** на следующие объекты и назначьте роль только служебной записи.
При использовании групп доступа включите роль в профиль её выделенной группы.

| Объект | Поля, используемые читателем |
| --- | --- |
| Регистр накопления `Продажи` | Обороты ресурсов `Количество`, `Стоимость` |
| Регистр накопления `ЗакупкиТоваров` | Обороты ресурсов `Количество`, `Сумма` |
| Документ `ЗаказПокупателя` | Номер, номер сайта, дата, статус, признак отмены, сумма и стандартные поля ссылки и пометки удаления. Из табличной части «Товары» читаются номер строки, номенклатура, характеристика, количество и отметка отмены. |
| Регистр сведений `СостояниеОплатыЗаказаПокупателя` | Последнее состояние оплаты конкретного заказа |
| Регистр сведений `СостояниеДоставкиЗаказаПокупателя` | Последнее состояние доставки конкретного заказа |

В штатных ролях «Чтение заказов» и «Чтение заказов покупателей» найдено право «Изменение»
на регистры состояний оплаты и доставки. В ответе отображаются статус, сумма, до 25 строк
состава и подтверждённые состояния оплаты и доставки. Поля покупателя, телефона,
адреса, трек-номера и реквизитов платежа в запросы читателя не входят.

## Запросы и проверка

- «Какие продажи за прошлый месяц?» даёт общий оборот регистра продаж за период.
- «Покажи закупки с 1 по 20 ноября» даёт общий оборот регистра закупок за период.
- «Проверь статус заказа №000000123 за 2026 год» ищет точный номер документа или сайта
  в указанном году. Номер после «заказ №» или «заказ #» берётся из исходной реплики
  с сохранением буквенного префикса и начальных нулей. При нескольких указанных номерах
  или совпадении нескольких документов чат просит уточнить номер.

Даты отчёта включительны, предельный период 366 дней. Суммируются обороты по базе,
количество указано в учётных единицах. Отчёт по отдельному товару, магазину или поставщику
требует отдельного запроса к источнику. В текущем интерфейсе доступен общий итог.

Клиентский виджет использует источник витрины. Серверная роль покупателя не вызывает
маршруты внутреннего отчёта и поиска заказа. Ответы менеджера формируются из возвращённых
полей, модель распознаёт запрос и период или номер.

После назначения роли сделайте резервную копию `onec_reader_windows.py` в каталоге
установки читателя на Hoster. Замените его файлом из `manager-demo/web` и перезапустите
задачу `HardPro-Onec-Reader`. Для сервера чата обновите `catalog_api.py` и
`manager_reports.py` и перезапустите `hardpro-catalog.service`.

Для приёмки проверьте пробное чтение каталога. Сверьте одну карточку с точной
розничной ценой и свободным остатком.
Сравните сводки за один закрытый день с регистрами 1С и найдите один заранее известный
заказ. При ошибке зафиксируйте, какой из трёх источников не прочитался.

25 ноября 2026 года обновлены читатель на Hoster и сервер чата. Через рабочий API
проверены цены и свободные остатки по капам BoyBo, обе сводки за закрытый день,
существующий заказ с оплатой и доставкой и ответ на отсутствующий номер. Запрос
к менеджерской выдаче с токеном покупателя получил HTTP 401. Обычный вопрос и
проверка связи после подбора товаров дали отдельные ответы. Автопроверка на сервере
прошла 26 тестов.

## Полный снимок каталога

Снимок на 25 ноября содержит 4 587 товаров с непустым кодом, 21 015 характеристик
этих товаров и 1 481 строку «Без характеристики». Коды и наименования каталога
проверены по номенклатуре MCP. Карточки включают полное наименование, вид товара,
производителя и описание до 512 символов, если поле заполнено. Для каждой
характеристики сохранены розничная цена в рублях и свободные количества с отметкой
времени чтения. Варианты без подтверждённой цены имеют значение `null`.

Для обновления выгрузите через MCP страницу активного справочника
`Номенклатура` без групп, по возрастанию кода, пока страницы не закончатся.
Соберите JSONL с полями `code`, `title`, `full_name`, `manufacturer`, `kind`,
`description`. Передайте эту выгрузку и путь результата в
[`export_catalog_knowledge.py`](../manager-demo/web/export_catalog_knowledge.py).
Запускайте скрипт в окружении читателя с настроенным `ONEC_READER_CONFIG`.
Он подтверждает совпадение каталога по каждому коду и наименованию, затем читает
цены и остатки партиями до 24 товаров и атомарно записывает закрытый JSON.
Сохраните его под именем `catalog-knowledge.json` в локальном каталоге данных 1С
сервера чата, рядом с текущим снимком. В Git хранятся код выгрузки и сводные замеры.

Менеджер загружает индекс из снимка младше суток и обновляет его фоновым чтением
справочника. Цены и свободные количества подтверждаются запросами к рабочей 1С.
При сбое связи чат помечает дату архивных остатков и сообщает статус свежих цен.
Сайт и внутренняя 1С используют отдельные источники розничных данных.
