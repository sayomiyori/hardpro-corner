# Qwen3.8 Flash Next на трёх RTX 3090

28 ноября 2026 года. Один процесс llama.cpp загрузил Qwen3.8 Flash Next UD-IQ4_XS на три RTX 3090. Перенос экспертов MoE из оперативной памяти на GPU увеличил медиану генерации с 46,50 до 72,03 токена/с. Измерения относятся к короткому одиночному запросу.

## Оборудование

AMD EPYC 7543, 503 ГиБ ОЗУ, три RTX 3090 по 24 ГиБ. Версии ядра Linux и открытого модуля NVIDIA — 6.8.0-151 и 580.178.04. Драйвер сообщает совместимость с CUDA 13.0, тестовый PyTorch 2.9.1 собран с CUDA 12.8. DKMS показывает gpu-unlock 2.0.0 для загруженного ядра. В журнале текущей загрузки у каждого из трёх PCI-устройств есть отдельная запись «unlocked».

| GPU | PCIe под нагрузкой | Температура в конце короткого теста | Мощность в момент опроса |
| --- | --- | ---: | ---: |
| 0 | Gen4 ×16 | 56 °C | 304 Вт |
| 1 | Gen4 ×16 | 48 °C | 287 Вт |
| 2 | Gen4 ×16 | 58 °C | 304 Вт |

На каждой карте по очереди три секунды умножали FP16-матрицы 2048 × 2048, заполненные значением 0,5. Все элементы результата равны 512. По NVML у пары 0–1 топология PHB, у двух других пар NODE. Для всех шести направлений драйвер возвращает CNS на P2P read/write, PyTorch возвращает False для peer access. После тестов в журнале ядра текущей загрузки не обнаружены Xid, ошибки AER и потеря GPU на шине. Тепловое равновесие при длительной полной нагрузке в этом опыте не измеряли.

## Как повторить сравнение

Использовали llama.cpp build 12375 (9d25e0014), четыре GGUF-шарда общим размером 93,67 ГБ. Освободили три GPU. Единственная разница между профилями — размещение тензоров экспертов. Таблица per_layer_token_embd.weight размером около 26,8 ГиБ в обоих случаях размещена в ОЗУ. [Опубликованные шарды Unsloth](https://huggingface.co/unsloth/Qwen3.8-Flash-Next-GGUF/tree/main/UD-IQ4_XS)

Общие параметры передаются в llama serve вместе с первым шардом модели.

~~~sh
--ctx-size 16384 --parallel 1 --gpu-layers all --split-mode layer \
--tensor-split 1,1,1 --fit off --flash-attn on --cache-type-k q8_0 \
--cache-type-v q8_0 --batch-size 2048 --ubatch-size 512 \
--threads 16 --threads-batch 32
~~~

Задать CUDA_DEVICE_ORDER=PCI_BUS_ID и CUDA_VISIBLE_DEVICES=0,1,2. Базовый вариант воспроизводит прежнее правило размещения экспертов при видимости трёх карт. Следующее выражение передаётся в --override-tensor.

~~~text
^per_layer_token_embd[.]weight=CPU,blk[.]([0-9]|1[01]|2[5-9]|3[0-4])[.]ffn_(up|down|gate|gate_up)_(ch|)exps=CPU
~~~

Для оптимизированного варианта использовать следующее правило.

~~~text
^per_layer_token_embd[.]weight=CPU
~~~

В каждом профиле выполнили один прогрев и три измерения. Запрос completion содержал 319 входных токенов, принудительную генерацию 96 токенов, температуру 0, seed 41 и отключённый кеш префикса. Тексты с номерами прогона повторялись в обоих профилях. Для обоих вариантов по PID проверили размещение одного процесса на всех GPU.

| --- | --- | ---: | --- | ---: |
| Прежнее правило | 8 542 / 11 332 / 17 602 | 319,65 | 41,38 / 46,93 / 46,50 | 46,50 |
| Эксперты на GPU | 21 250 / 21 854 / 20 308 | 1 038,64 | 68,80 / 72,20 / 72,03 | 72,03 |

Обработка входа ускорилась в 3,25 раза, генерация — в 1,55 раза. Через chat completions оба профиля ответили «42» на 23 + 19. Результаты при почти заполненных окнах 16K, 64K и 128K приведены ниже. Режим нескольких клиентов требует отдельного замера.

## Рабочие сервисы

Перед опытом менеджер Qwen3-14B-AWQ на GPU 0 показал 85,00 токена/с, чат 27B на GPU 1 — 68,35 токена/с (медианы трёх запросов по 64 выходных токена). На GPU 2 Hunyuan3D 2.1 Shape построила GLB по фотографии перчатки за 36,25 с. После опыта менеджер и чат ответили «42» на 17 + 25, очередь 3D-фабрики доступна и пуста. Flash Next запускалась временно.

## Почти полные окна 16K, 64K и 128K

На каждой длине один процесс обслуживал один запрос на трёх RTX 3090. На вход подавали точно отмеренный массив токенов синтетических складских записей. В окне оставляли 256 позиций и генерировали 128 токенов с температурой 0. Кеш префикса отключили. Время до первого непустого фрагмента текста (TTFT) измерял клиент на loopback после короткого прогрева. Загрузка GGUF и предварительная токенизация корпуса происходили до старта таймера. Decode — скорость фазы генерации по счётчику llama.cpp. Пики VRAM всей карты снимали через nvidia-smi с интервалом около полусекунды.

### Профили штатного движка

Установлены три профиля Flash Next с суффиксами 16K-3GPU, 64K-3GPU и 128K-3GPU. Для каждого окна выбрали наименьшее измеренное TTFT среди вариантов с K/V q8_0 и запасом порядка 0,5 ГиБ или больше на каждой карте. На 128K ubatch 2048 показал наименьшую задержку среди вариантов q8/q8, но оставил около 170 МиБ на GPU 1. Снижение точности V до q4_0 в этой серии замедлило генерацию.

Профили запускаются по запросу в период, когда все три карты освобождены. Штатные службы менеджера и 3D-фабрики используют GPU независимо от переключателя Hub. После серии 14B и 27B ответили «42» на 17 + 25, очередь 3D-фабрики была доступна и пуста. По журналу ядра текущей загрузки ошибок Xid и AER не обнаружено. Перед запуском проверьте их очереди. После теста остановите выбранный профиль и восстановите обычные службы. ### Спекулятивная генерация

У штатного build 12375 загрузка общей MTP-головы завершилась ошибкой отсутствующего token_embd.weight. В отдельной CUDA 12-сборке Unsloth b10715-mix-86bd2d3 голова shared-Q4_K_M заимствует тензоры основной модели. SHA-256 архива сборки сопоставлен с GitHub Releases, SHA-256 головы — с опубликованным LFS-объектом. Два черновых токена за шаг, черновик размещён на GPU 2. На 16K принято 77 из 100 предложенных токенов, на 64K — 75 из 104. Это сравнение полных конфигураций с разными версиями движка. На холодном длинном входе MTP увеличивает TTFT. [Описание головы и сборок](https://huggingface.co/unsloth/Qwen3.8-Flash-Next-GGUF/blob/main/MTP/README.md)

На 128K первая попытка MTP завершилась при выделении ещё 497 МиБ на GPU 2. Перенос экспертов блока 47 в ОЗУ позволил завершить запрос. Принято 74 из 105 предложенных токенов.

Для MTP используется отдельный пользовательский юнит с ручным запуском. В его EnvironmentFile задаются абсолютные пути FLASH_NEXT_SERVER, FLASH_NEXT_MODEL, FLASH_NEXT_DRAFT, длина FLASH_NEXT_CONTEXT и выражение FLASH_NEXT_PLACEMENT для --override-tensor. Значение для размещения таблицы эмбеддингов в ОЗУ приведено в основном сравнении выше. На сервере юнит проверен через systemctl с окном 131072 и размещением экспертов блока 47 в ОЗУ. На контрольной генерации он принял 36 из 53 черновых токенов. Запуск требует трёх свободных карт. [Юнит MTP](../local-llm/context/hardpro-flash-next-mtp.service)

### Проверка прямого обмена

Драйвер сообщает CNS для чтения и записи во всех парах. Вызов cuDeviceCanAccessPeer вернул 0 во всех шести направлениях. Линки NVLink неактивны. IOMMU работает с трансляцией. У всех карт BAR1 равен 256 МиБ, при этом первая карта объявляет максимум 256 МиБ, две другие — до 32 ГиБ. Эти измерения не выделяют единственную причину ограничения. NVIDIA указывает ограничения PCIe P2P при включённой IOMMU на Linux bare metal. Аппаратный мост для RTX 3090 соединяет пару карт. На этой машине выбран послойный GPU-параллелизм. Настройки загрузчика, модуль ядра и драйвер во время серии не изменялись.
