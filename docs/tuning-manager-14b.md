# Настройка Qwen3-14B-AWQ для менеджера HARD-PRO

24 ноября 2026 года сравнили настройки vLLM на одной RTX 3090. Во всех прогонах использовали те же веса Qwen3-14B-AWQ, контекст до 40 960 токенов, режим без thinking, включённый кеш префикса и vLLM 0.34.0. Кандидаты работали на отдельной RTX 3090. Сравнение скорости и памяти идёт с контролем на той же карте. [Параметры vLLM 0.34.0](https://docs.vllm.ai/en/v0.34.0/cli/bench/forward/) · [Карточка Qwen3-14B-AWQ](https://huggingface.co/Qwen/Qwen3-14B-AWQ)

## Что проверили

Скрипт отправляет 30 запросов с вымышленными артикулами. Сначала восемь последовательных запросов, затем три волны по четыре коротких запроса. В двух волнах запрос примерно на 7,7 тыс. токенов стартует одновременно с тремя короткими. Последние два запроса проверяют вход примерно в 38 тыс. токенов и повтор с тем же префиксом. Ответы сверяются с ожидаемыми данными, включая подтверждённый ноль, отсутствующую складскую строку и устаревший снимок.

TTFT — время до первого токена ответа. Показатели коротких запросов даны медианой или P95 конечной выборки. Для p95 смешанного сценария использованы шесть коротких ответов. Один длинный холодный запрос на профиль показывает время контрольного случая. JSONL хранит метрики и признаки правильности, без текстов ответа. Проверка относится к API модели и учебным данным.

## Сравнение профилей

Контроль использует лимит VRAM `0,92`. Кандидаты используют `0,82` и меняют по одному параметру относительно варианта FP16. Профиль с явно заданным батчем `2048` повторяет штатное значение для OpenAI API на RTX 3090 в этой версии vLLM. Батч `1024` проверяет более мелкое разбиение длинного prefill. У N-gram задано три токена на шаг и окно поиска четыре токена. [Настройка батча vLLM](https://docs.vllm.ai/en/v0.34.0/configuration/optimization/#chunked-prefill) · [N-gram в vLLM](https://docs.vllm.ai/en/v0.34.0/features/speculative_decoding/n_gram/)

Оба запуска FP8 E4M3 завершились до замеров. Автовыбор бэкенда дошёл до JIT-сборки FlashInfer, которой нужен отсутствующий на стенде `nvcc`. При явном выборе Triton vLLM сообщил, что FP8 KV-кеш не поддерживается на RTX 3090 (SM 8.6) этим бэкендом.

## Выбор профиля

**Для проверенной нагрузки менеджера выбран vLLM 0.34.0, AWQ-Marlin, FlashAttention, FP16 KV-кеш, окно 40 960 и `--gpu-memory-utilization 0.82`.** Thinking выключен, кеш префикса включён, планировщик использует штатный батч 2048.

Два раздельных запуска с эффективными настройками FP16/0,82 дали 60 правильных ответов из 60. Повторные запросы завершились без вытеснения KV-кеша. Из контрольных 22 182 МиБ освободились 2 402 МиБ, около 2,35 ГиБ. Размер пула KV снизился с 69 632 до 54 272 токенов. Одиночный вход 38 009 токенов прошёл, возможности одновременной обработки нескольких запросов предельной длины стали меньше. Короткие запросы в четырёх одновременных потоках дали около 135–139 токенов/с в контрольном прогоне и варианте FP16/0,82 без явного переопределения батча. Эти малые выборки показывают сопоставимую скорость.

N-gram потреблял меньше VRAM, но уменьшил пул KV до 48 128 токенов и удлинил тёплый ответ на длинный вход с 0,43 до 1,10 с. Для менеджера важнее сохранить этот быстрый путь.

Эксперимент остановила отдельная штатная перезагрузка. Замер с батчем 1024 прервался до запуска профиля. После загрузки конфигурация хоста изменилась, числовое сравнение построено только по прогонам до неё. Оба рабочих движка и веб-чат поднялись, менеджер сохранил рабочий лимит `0,92` и окно 40 960. Лимит `0,82` проверен как кандидат на отдельной карте.

## Как повторить

Для контрольного замера запустите Qwen3-14B-AWQ через vLLM с `--max-model-len 40960`, `--enable-prefix-caching`, `--reasoning-parser qwen3` и `--default-chat-template-kwargs.enable_thinking false`. Сведите остальные параметры к настройкам из таблицы, используйте одну GPU и проводите сравнение на свободном слоте. Скрипт ожидает vLLM с доступными `/tokenize` и `/metrics`. Если API защищён, передайте ключ через переменную `VLLM_API_KEY` в закрытом окружении.

```bash
python3 systemd/tuning-14b/bench.py \
  --port 18000 --gpu 1 --model manager --tag fp16-082 \
  --output ./tuning-14b-results.jsonl
```

Без `--rapid` выполняются длинные контрольные запросы. Для повторения холодных измерений на том же процессе меняйте `--tag`, чтобы получить новый префикс.
