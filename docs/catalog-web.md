# Каталог в браузере

Менеджер работает в Open WebUI, покупатель — в виджете HARD-PRO на странице магазина. Обычные вопросы обрабатывает локальная модель 14B через vLLM. Для вопросов о товарах приложение сверяет сведения с источником, доступным для роли.

## Источник для каждой роли

| Клиент | Где берутся сведения |
| --- | --- |
| Менеджер | Каталог, розничные цены и свободные остатки рабочей 1С. Строки выдачи содержат модель, варианты и данные по магазинам. Пропущенная строка склада означает неизвестное количество. При сбое читателя помощник указывает дату выгрузки и показывает доступные архивные остатки. |
| Покупатель | При каждом вопросе витрина пересчитывает доступное количество через тот же метод, что карточка товара. Он учитывает активность варианта, резервы с действующим сроком и отправленные заказы. Приложение проверяет публикацию и видимость карточки. |

## Путь запроса покупателя

Питомец закреплён справа посередине. На компьютере он открывает боковую панель, на телефоне — полноэкранный диалог. Открытие занимает 300 и 200 мс соответственно. Системная настройка уменьшения движения отключает анимацию. Переписка живёт в памяти страницы. При обновлении страницы или нажатии «Новый диалог» она очищается.

1. Браузер отправляет вопрос на HTTPS-маршрут магазина `/catalog-assistant/ask` с той же авторизацией, что и витрина.
2. Nginx передаёт запрос через закрытый SSH-порт в `hardpro-widget` на Ubuntu. В обратном направлении виджет читает снимок опубликованных вариантов из внутреннего маршрута этой витрины.
3. Помощник отвечает на вопросы о товарах по витрине и учитывает категорию, модель, вариант и выбранный магазин. Публичные условия магазина и проверенные консультации берутся из [справки покупательского чата](storefront-knowledge-2026-11-25.md). Локальная модель ведёт свободный диалог. Кеш снимка живёт до восьми секунд. Момент снимка передаётся в ответе каталога. При недоступности источника интерфейс предлагает повторить запрос.

## Службы и сверка

На Ubuntu включены пользовательские службы `hardpro-stage-link`, `hardpro-widget`, `hardpro-vllm`, `hardpro-openwebui` и `hardpro-catalog`. Постоянный пользовательский менеджер systemd запускается с системой. Пример службы туннеля находится в `manager-demo/web/hardpro-stage-link.service`. На стенде для отдельного SSH-ключа разрешены только два направления loopback. Ключ и проверенный список ключей узла хранятся у владельца службы.

Open WebUI работает в личном однопользовательском режиме. Локальный сценарий `open-catalog.cmd` открывает его через SSH и запускает локальную копию витрины. HTTPS-стенд связывается с Ubuntu самостоятельно.

Для проверки откройте одну модель, уточните цвет и размер, затем поменяйте город. Сверьте оба числа по одному SKU в карточке. Для независимой проверки остановите посредники на рабочем компьютере и выполните тот же сценарий с тестового сервера. 19 ноября 2026 года такая сверка прошла, включая отсутствующий остаток в одном из магазинов. В браузере проверены обе ширины, история после обновления, новый диалог и возврат фокуса к питомцу.

## Подключение рабочей «Розницы» для менеджера

На сервере 1С обработчик `manager-demo/web/onec_reader_windows.py` использует локальный 64-битный COMConnector и отдельную учётную запись. Ей нужны роли «Запуск внешнего соединения», «Чтение информации по номенклатуре» и «Чтение остатков товаров». Сверять права на чтение цен и других полей следует на фактической версии конфигурации. Обработчик выполняет заранее заданные запросы. Тексты вопросов и запросы на языке 1С через сеть ему не передаются.

| Маршрут | Данные |
| --- | --- |
| `GET /v1/catalog?after=…` | Порция до 64 действующих карточек с характеристиками. Для следующей страницы берётся курсор из ответа. |
| `GET /v1/stock?product=…&variant=…` | Запись по паре UUID и двум заранее заданным физическим складам. В ответе есть количество, резерв и момент чтения. |
| `GET /v1/offers?products=…` | До 24 товаров за запрос. Проверенные розничные цены и остатки по точным характеристикам. |
| `GET /v1/details?product=…` | Описание и свойства одной карточки. |

Фразу «проверь подключение к 1С» можно отправить в текущем диалоге после любой подборки. Приложение делает пробное чтение страницы справочника с обходом кеша и временной паузы после ошибки. После успеха оно указывает время проверки и возобновляет попытки онлайн-поиска. При ошибке ответ содержит статус чтения.

Роли для товарного каталога, внутренних сводок и поиска заказов перечислены
в [матрице доступа менеджера](manager-data-access.md).

Для подготовки нового каталога Hoster запустите `prepare_reader_host.ps1` под владельцем установки. Он закрывает ACL каталога, готовит окружение, выпускает закрытый ключ на Hoster и сохраняет публичный запрос `private/server.csr`. Этот запрос подписывает собственный центр сертификации канала. Верните на Hoster сертификат сервера с SAN адреса подключения и открытый сертификат центра. Для привязки к служебной записи команда `venv\Scripts\python.exe prepare_reader_windows.py enroll private` запрашивает пароль скрытым вводом и проверяет вход в рабочую базу до записи DPAPI-файла.

Службе Windows нужны Python с pywin32, совместимый COMConnector, собственный сертификат сервера и доверенный сертификат для аутентификации клиента. В её приватной конфигурации задаются `bind`, `port`, `cert`, `key`, `client_ca`, `password_dpapi` и список двух UUID `warehouses`. Файл пароля содержит результат Windows DPAPI для UTF-8 и доступен только службе и администратору. Ограничьте входящий маршрут до узла Ubuntu.

### Проверка COMConnector на Windows

Если при `enroll` появляется `AttributeError: V83.COMConnector.Connect`, Python создал COM-объект, но не смог найти его метод. Проверка пароля начинается только после вызова `Connect`. Выполните блок в PowerShell из каталога читателя. Он использует то же окружение Python, выводит имя библиотеки и идентификатор метода либо исходный код сбоя COM. Подключение к базе для этих проверок не открывается.

```powershell
@'
from pywintypes import com_error
from win32com.client import Dispatch

try:
    com = Dispatch("V83.COMConnector")._oleobj_
except com_error as error:
    raise SystemExit(f"COMConnector HRESULT=0x{error.hresult & 0xffffffff:08X}") from None

for name, check in (
    ("TypeLib", lambda: com.GetTypeInfo().GetContainingTypeLib()[0].GetDocumentation(-1)[0]),
    ("Connect DISPID", lambda: com.GetIDsOfNames(0, "Connect")),
):
    try:
        print(name, check())
    except com_error as error:
        print(f"{name} HRESULT=0x{error.hresult & 0xffffffff:08X}")
'@ | .\venv\Scripts\python.exe -
```

На проверенной платформе 8.3.27.1688 результат — `TypeLib V83` и `Connect DISPID 11`. Код `0x8002801D` указывает на незарегистрированную библиотеку типов. Для этого случая 1С документирует ручную регистрацию установленной `comcntr.dll`. При другом коде сначала проверьте регистрацию и путь конкретного компонента. [Документация 1С о компонентах внешнего соединения](https://its.1c.ru/db/content/edtdoc/src/topics/t000419.html) · [Коды загрузки библиотеки типов Windows](https://learn.microsoft.com/en-us/windows/win32/api/oleauto/nf-oleauto-loadregtypelib).

Для восстановления запустите 64-битный PowerShell от имени администратора. Блок берёт путь к DLL из действующей машинной регистрации, показывает путь и версию файла и регистрирует этот же компонент.

```powershell
& {
    $ErrorActionPreference = 'Stop'
    if (-not [Environment]::Is64BitProcess) { throw 'Open 64-bit PowerShell.' }
    $root = 'Registry::HKEY_LOCAL_MACHINE\SOFTWARE\Classes'
    $clsid = (Get-Item -LiteralPath "$root\V83.COMConnector\CLSID").GetValue('')
    $path = (Get-Item -LiteralPath "$root\CLSID\$clsid\InprocServer32").GetValue('')
    $dll = Get-Item -LiteralPath $path
    if ($dll.PSIsContainer -or $dll.Name -ine 'comcntr.dll') { throw 'Expected the registered comcntr.dll.' }
    Write-Host "$($dll.FullName) ($($dll.VersionInfo.FileVersion))"
    $result = Start-Process -FilePath "$env:windir\System32\regsvr32.exe" `
        -ArgumentList ('"{0}"' -f $dll.FullName) -Wait -PassThru
    if ($result.ExitCode -ne 0) { throw "regsvr32 exit code $($result.ExitCode)" }
}
```

После успешной регистрации вернитесь в исходное окно PowerShell и повторите проверку. Когда обе строки выводятся без `HRESULT`, выполните `.\venv\Scripts\python.exe .\prepare_reader_windows.py enroll .\private` и введите пароль в появившемся приглашении. Сообщение «Учётная запись подтверждена 1С» означает, что сеанс открывается под нужным пользователем и пароль сохранён через DPAPI.

### Первый запуск читателя

Сохраните подписанный сертификат сервера как `private/server.pem`. Он должен содержать адрес из конфигурации Ubuntu в SAN и назначение `serverAuth`. Из каталога читателя запустите `.\venv\Scripts\python.exe .\onec_reader_windows.py .\reader.json`. При успешной загрузке сертификата и ключа процесс слушает адрес и порт из `reader.json` и ожидает запросы. Проверить локальный сокет можно из второго окна PowerShell через `Get-NetTCPConnection -State Listen -LocalPort` с портом из конфигурации. Остановить пробный запуск можно сочетанием Ctrl+C в первом окне.

### Проверка маршрута с Ubuntu

На Ubuntu приватный JSON задаёт `host`, `port`, `ca`, `cert`, `key` и `warehouses` в формате «название → UUID». Указанный хост должен совпадать с именем или IP в сертификате сервера. Этот файл подключается к `hardpro-catalog.service` через переменную `ONEC_READER_CONFIG`. Список вариантов кешируется на пять минут. При выборе размера приложение запрашивает регистр заново, вычитает резерв и отмечает пропущенную строку как неизвестный остаток. При недоступной 1С менеджер увидит сообщение о недоступности источника. Архивный режим явно подписан датой выгрузки.

Для SSH-туннеля добавьте в приватный JSON `"ssh_relay": true`. Клиент подключится к порту `port` на `127.0.0.1` и проверит сертификат читателя по значению `host`.

20 ноября 2026 года Ubuntu прочитала 22 496 строк рабочего каталога за 63 секунды. Проверочный запрос через Open WebUI вернул время чтения и свободный остаток на обоих складах. Первый ответ API с пустым кешем занял 61 секунду, повторный — 0,8 секунды. Остатки запрашиваются при каждом выборе варианта, каталог перечитывается после истечения пяти минут.

Канал проходит через SpaceWeb. SSH-ключи ограничены пробросом одного порта на loopback, а служба 1С проверяет клиентский сертификат. Туннель на Ubuntu запускается автоматически. SpaceWeb проверяет отклик только у SSH-соединения Hoster и освобождает порт после трёх проверок без ответа с интервалом 15 секунд.

На Hoster задачи `HardPro-Onec-Reader` и `HardPro-Onec-Tunnel` запускаются при загрузке Windows под LocalService. Если процесс остановился, Планировщик повторяет запуск каждую минуту. При установке проверили чтение 1С и аутентификацию SSH от имени LocalService, затем подтвердили, что оба процесса стартовали в системном сеансе и Ubuntu прочитала остатки. После принудительного закрытия только SSH-сеанса Hoster переподключился за 34 секунды, повторное чтение остатков прошло. Hoster в ходе проверки не перезагружали.

## Сайт после обновления 20 ноября 2026 года

Помощник выбирает опубликованные карточки, уточняет модель, размер и цвет, показывает цену и наличие в магазинах. Ссылки формируются по числовым идентификаторам карточки и варианта. Контакты и часы работы берутся из того же справочника, что раздел контактов. Комплект подбирается по виду спорта или списку вещей. При известном городе используются варианты для этого магазина. Для одежды можно указать размер или рост. Если запрошенных позиций нет или минимальная сумма превышает бюджет, помощник пишет об этом.

Остаток берётся из того же снимка, что обслуживает карточки магазина. Зачёркнутая цена выводится с явной подписью. История цен хранится отдельно по паре товар–вариант. `hardpro-price-observation.timer` снимает публичную цену раз в день, хранит до 90 дней и догоняет пропущенный запуск. В ответе сравниваются зафиксированные значения и текущая цена. Первое снятие на стенде дало 57 цен. До появления следующего значения помощник сообщает, что сведений для вывода об изменении мало. Движение между ежедневными наблюдениями может остаться незамеченным.

### Границы и данные

- Вступление к менеджерской подборке формируется из данных 1С. В покупательском чате обработчик подставляет подтверждённые сведения о товаре и учитывает предыдущие уточнения. Доступные источники определяет роль HTTP-запроса. Цена, количество и ссылки собираются приложением из проверенных полей. Браузер вставляет строки через `textContent` и проверяет тип и маршрут каждой ссылки. Ключи и команды в модельный запрос не передаются.
- Типичные телефонные номера, email, реквизиты заказа и распространённые упоминания травм отсекаются в браузере. На сервере действует повторная проверка. На вопросы о травмах и симптомах помощник рекомендует обратиться к врачу. Такие сообщения не повторяются в диалоге. Очистка сеанса удаляет текст из интерфейса, HTTP-ответы идут с запретом кеширования, а маршруты виджета работают без журнала сообщений. Произвольный свободный текст может содержать сведения, которые правила не распознают.
- Браузер обращается по HTTPS к магазину. Прокси передаёт запросу только необходимые заголовки и ограничивает частоту запросов и размер тела. Стенд закрыт авторизацией. Публичная проверка для запуска требует сверить реальные журналы и сроки их хранения, расположение баз и резервных копий, основания обработки по статье 6, политику и сведения об уведомлении Роскомнадзора по статье 22. Если основание — согласие, оно оформляется отдельно. Сведения о здоровье относятся к специальным категориям. [152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/) · [Правила розничной продажи с сентября 2026 года](https://zpp.rospotrebnadzor.ru/news/federal/594255).
- Холодный ответ в браузерном сценарии занял 1,33 с, следующие серверные ответы около 0,2 с. Проверены ссылка на конкретный SKU, остаток выбранного магазина, две позиции комплекта, контакты, история с одним наблюдением, ответы о травме и служебных инструкциях, локальный отказ отправки телефона и очистка при обновлении страницы. Раздел работает на закрытом HTTPS-стенде.
