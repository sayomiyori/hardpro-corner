# Помощник менеджера HARD-PRO

Менеджер спрашивает о товаре, размере или наличии. Помощник показывает найденные варианты, склад и время проверки, затем предлагает черновик для ручной отправки.

## Проект веб-версии и первый запуск модели

- vLLM под systemd обслуживает модель на одной RTX 3090. API модели принимает запросы только с самого сервера.
- Один сервис на Python, FastAPI и Pydantic обслуживает внутреннюю страницу, проверяет параметры запроса и формирует ответ.
- SQLite хранит локальную копию каталога и остатков. Точный поиск по коду, артикулу и штрихкоду идёт по полям. Для названий и описаний используем FTS5.
- Модель разбирает свободный текст и формулирует черновик. SKU, цены, остатки, ссылки и время чтения подставляет приложение из проверенных данных.
- Для демонстрации выбран официальный Qwen3-14B-AWQ в формате Safetensors с контекстом 4096 токенов и одним одновременным запросом. Файлы весов занимают 9,29 ГиБ. Ранее рассматривали Qwen3.5 9B в Ollama.

## Каталог и наличие

1. Загружаем проверенную подборку из 31 карточки и 57 SKU. Варианты связываем по паре UUID товара и характеристики. Если поисковый ключ совпал с несколькими вариантами, просим уточнить.
2. Переиспользуем ограниченный запрос к регистру товаров на складах через существующий Windows-адаптер. Сборщик читает количество и резерв отдельно по Севастополю и Симферополю. Перед расписанием проверяем права сервисной учётки, время чтения и нагрузку на 1С.
3. Сервис принимает результаты по закрытому каналу, проверяет идентификаторы и время чтения, затем фиксирует согласованную партию в локальной базе. Устаревшее обновление не перезаписывает более новое.
4. Свободный остаток по 1С считаем после резерва 1С. Доступность заказа на сайте требует отдельного учёта удержаний интернет-заказов. Если строка отсутствует или данным больше пяти минут, помощник сообщает, что наличие не подтверждено. Подтверждённый ноль означает отсутствие товара. Пять минут — предложенный порог пилота, расписание зависит от замеров.

## Прогон на учебном каталоге

19 ноября 2026 года команда `hp-manager` проверена через локальный API vLLM 0.34.0 на одной RTX 3090. Команда без аргументов открывает диалог, команда с вопросом в кавычках выдаёт один ответ. Веса и токенизатор лежат на диске моделей. В интерактивном режиме передаются две последние пары реплик.

Исходные данные хранятся в [учебном каталоге](../manager-demo/catalog-demo.json). Для каждой характеристики и склада приложение вычисляет свободное количество после резерва. Момент проверки фиксирован относительно часов учебного снимка. Для просроченной строки в контекст передаётся только статус и время проверки. Для отсутствующей строки приложение добавляет явный статус. Доступа к операциям бронирования и рабочей 1С у демо нет.

При первой проверке два ответа превратили отсутствие данных в нулевую доступность. При уточнении поиска на другом складе модель однажды предложила другой вес. После явного представления неизвестных остатков и закрепления характеристики при переходе между складами сверены [10 вопросов с ожидаемыми результатами](../manager-demo/questions.json), ещё четыре формулировки и диалог. В финальном прогоне ответы соответствовали учебным данным. Медиана десяти отдельных запросов после прогрева составила 0,58 с. Для реальных данных требуется отдельная выборка от менеджеров.

## Поиск по полному каталогу

Команда `hp-manager --onec` открывает поиск по всем карточкам сохранённой выгрузки. Для разового ответа добавьте вопрос в кавычках. В диалоге можно уточнить размер, цвет, модель или город, выбрать строку командой `№2` и посмотреть следующую страницу командой `ещё`. Команда `/выход` завершает диалог.

Для полного импорта вместо `--selection` укажите `--warehouses "$WAREHOUSES_JSON"`. Это отдельный JSON-словарь с идентификаторами и названиями разрешённых физических складов. Сохраните результат вне Git как `~/.local/share/hardpro/onec-pilot/full-catalog.json` с правами 0600. Снимок содержит активные карточки и характеристики. Для ссылки из регистра без записи в справочнике выводится отдельная характеристика с её идентификатором. Одинаковые названия у разных ссылок остаются отдельными строками.

Модель получает вопрос и предыдущие условия поиска, затем возвращает название или артикул, характеристику и склад в JSON. Приложение ищет по локальным строкам каталога, учитывает размер и цвет из самого вопроса и запрашивает уточнение при нескольких совпадениях. Значение свободного остатка и момент выгрузки выводит приложение. Отсутствующая строка в регистре даёт ответ «количество неизвестно». Для объёма этой выгрузки достаточно поиска в памяти процесса.

В снимке 536 карточек, 3 431 действующая характеристика и три дополнительные ссылки из регистра без названия в справочнике. Все 1 237 сохранённых складских строк сверены с первоначальными ответами 1С. В локальном прогоне Qwen3-14B-AWQ прошло 17 контрольных реплик. Ещё на 24 карточках, выбранных отдельно, получено 20 ответов и четыре уточнения. В проверке используются оба розничных склада; время остатков указано перед ответом. Чтобы подтвердить сегодняшнее наличие, потребуется чтение более свежего источника.

## Первый прогон на шести характеристиках

`hp-manager --onec` на сервере открывает диалог и показывает доступные варианты. Для одного вопроса передайте текст следующим аргументом. Обёртка отправляет модели только отобранные поля и указывает момент чтения регистра перед каждым ответом. Источник хранится в закрытом `~/.local/share/hardpro/onec-pilot/catalog.json`. Учебный режим по-прежнему открывается командой `hp-manager`.

```sh
python manager-demo/import_onec_snapshot.py --capture "$CAPTURE_DIR" --selection "$SELECTION_JSON" --manifest-sha256 "$MANIFEST_SHA256" --output "$PRIVATE_DIR/catalog.json"
python manager-demo/test_import_onec_snapshot.py
```

Импортёр рассчитан на формат сохранённого чтения регистра «ТоварыНаСкладах» рабочей «Розницы». Контрольную сумму манифеста берут из отдельной квитанции завершённого чтения. Файл отбора содержит словарь `warehouses` (UUID физического склада и подпись) и список `variants` с полями `product_uuid` и `characteristic_uuid`. Файлы отбора, оригиналы и собранную подборку хранят вне Git. При ошибке проверки прежний результат сохраняется.

В проверке 19 ноября использован снимок от 18 ноября 2026 года, 12:05 МСК. Шесть характеристик трёх товаров имели по строке на каждом из двух складов. Эталон рассчитан из сохранённых ответов исходного запроса до нормализации, по формуле `КоличествоОстаток − РезервОстаток`. Через установленную команду выполнены шесть вопросов про оба склада и двенадцать про отдельный склад. Все двенадцать значений в обоих прогонах совпали с эталоном. Также проверены вопрос о сегодняшнем наличии, отсутствующий размер, уточнение размера и учебный режим. Резерв в этой реальной подборке нулевой. Для ненулевого резерва, явного нуля, отсутствующей строки и изменения содержимого выгрузки есть отдельный тест на вымышленных данных.

## Первый контрольный прогон на данных менеджеров

Берём 50 обезличенных вопросов менеджеров. Включаем точный поиск, неоднозначные варианты, размеры, оба склада, нулевой остаток и недоступность 1С. Отдельно оцениваем долю пригодных черновиков, задержку ответа и VRAM на одном и двух одновременных запросах. Подмена SKU, выдуманная цена или подтверждение устаревшего остатка блокируют запуск пилота.
