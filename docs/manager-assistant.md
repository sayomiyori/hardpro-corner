# Помощник менеджера HARD-PRO

Менеджер спрашивает о товаре, размере или наличии. Помощник показывает найденные варианты, склад и время проверки, затем предлагает черновик для ручной отправки.

## Архитектура пилота

- Ollama под systemd обслуживает модель на одной RTX 3090. API модели принимает запросы только с самого сервера.
- Один сервис на Python, FastAPI и Pydantic обслуживает внутреннюю страницу, проверяет параметры запроса и формирует ответ.
- SQLite хранит локальную копию каталога и остатков. Точный поиск по коду, артикулу и штрихкоду идёт по полям. Для названий и описаний используем FTS5.
- Модель разбирает свободный текст и формулирует черновик. SKU, цены, остатки, ссылки и время чтения подставляет приложение из проверенных данных.
- Стартовая модель — qwen3.5:9b-q4_K_M с контекстом 4096 токенов и одним одновременным запросом. Для проверки качества сравниваем её с qwen3.8:27b-q4_K_M на одинаковых вопросах и одной карте.

## Каталог и наличие

1. Загружаем проверенную подборку из 31 карточки и 57 SKU. Варианты связываем по паре UUID товара и характеристики. Если поисковый ключ совпал с несколькими вариантами, просим уточнить.
2. Переиспользуем ограниченный запрос к регистру товаров на складах через существующий Windows-адаптер. Сборщик читает количество и резерв отдельно по Севастополю и Симферополю. Перед расписанием проверяем права сервисной учётки, время чтения и нагрузку на 1С.
3. Сервис принимает результаты по закрытому каналу, проверяет идентификаторы и время чтения, затем фиксирует согласованную партию в локальной базе. Устаревшее обновление не перезаписывает более новое.
4. Свободный остаток по 1С считаем после резерва 1С. Доступность заказа на сайте требует отдельного учёта удержаний интернет-заказов. Если строка отсутствует или данным больше пяти минут, помощник сообщает, что наличие не подтверждено. Подтверждённый ноль означает отсутствие товара. Пять минут — предложенный порог пилота, расписание зависит от замеров.

## Первый контрольный прогон

Берём 50 обезличенных вопросов менеджеров. Включаем точный поиск, неоднозначные варианты, размеры, оба склада, нулевой остаток и недоступность 1С. Отдельно оцениваем долю пригодных черновиков, задержку ответа и VRAM на одном и двух одновременных запросах. Подмена SKU, выдуманная цена или подтверждение устаревшего остатка блокируют запуск пилота.
