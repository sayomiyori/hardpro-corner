В момент проверки витрина передавала 373 опубликованных раздела, 31 товарную карточку и 57 вариантов. Фото модели есть у всех 31 товаров. Собственное фото есть у 23 вариантов. Ссылки карточек и фото формируются из данных витрины и проверяются до вывода.

После выкладки набор из 100 прежних вопросов прошёл через работающий HTTP-сервис. Сохранены цены, варианты, остатки и товарные ссылки. Изменения отдельных ответов касаются формулировок, карточек и передачи к менеджеру. Пройдены 19 серверных тестов с синтетическими данными и клиентские проверки приватности, ссылок, фото и ограничения повторов.

Внешний HTTPS-адрес во время прогона завершался тайм-аутом. Для браузерной проверки использован локальный предпросмотр через существующий закрытый канал к стенду. В Chrome загружались витрина, её фото и реально развёрнутый сервис ответов. Разметка виджета была получена из той же версии PHP, JavaScript и CSS, которая установлена на стенде. Проверка внешней доступности и нагрузки остаётся отдельной.

## Контекст открытой карточки

В начале диалога виджет передаёт идентификаторы открытого товара и выбранного варианта, а также выбранный город. Ответ на «а такие же на 14 унций есть?» сохраняет модель и цвет, если исходный вариант присутствует в опубликованном каталоге. Явный запрос другого товара или города меняет поиск. Сервер игнорирует SKU, который не принадлежит открытой карточке, и сверяет цену, остаток и ссылку по опубликованному каталогу.

25 ноября 2026 года проверены ответы HTTP-сервиса с синтетическим каталогом, рендер PHP и отправка из JS-виджета. Прежние клиенты могут отправлять только список реплик. Тестовую витрину при выкладке следует обновлять после сервиса ответов, чтобы он уже принимал поле контекста.

В тот же день сервис и виджет обновлены на тестовом стенде. В Chrome через закрытый предпросмотр открыли карточку синих Fairtex BGV1 One на 10 oz в Симферополе. Первая реплика «а такие же на 16 унций есть?» вернула синий вариант, цену 15 999,99 ₽ и одну доступную пару. Открыли карточку по ссылке из чата и сверили тот же вес, город, цену и остаток. На 14 oz в этой линейке чат указал отсутствие варианта и показал доступные веса. Внешний HTTPS отвечал запросом авторизации. Использован закрытый канал с каталогом и сервисом стенда и той же версией виджета.

## Передача вопроса сотруднику в MAX

Кнопка «Подготовить вопрос» показывает одно редактируемое сообщение. Покупатель может убрать товар, вариант и магазин перед отправкой. Если автоматическая передача настроена, кнопка «Передать в MAX» отправляет вопрос в один рабочий чат через бота. После ответа API покупатель видит номер обращения и может назвать его сотруднику в официальном чате MAX. Если доставка не подтверждена, виджет предлагает прямой контакт. История переписки с покупателем в MAX не передаётся.

Сервис повторно проверяет товар и вариант по опубликованному каталогу и отклоняет вопросы с обнаруженными личными или платёжными данными. Для ограничения повторов сохраняются номер, статус и хеш обращения. Повторная отправка с тем же идентификатором возвращает квитанцию. Если MAX не подтвердил результат, сервер не отправляет второе сообщение автоматически. Квитанции старше суток удаляются при обработке следующего обращения.

Для подключения добавьте бота в рабочий чат MAX. В закрытом файле окружения сервиса задайте `MAX_SUPPORT_TOKEN`, `MAX_SUPPORT_CHAT_ID` и `MAX_SUPPORT_STATE` с абсолютным путём к доступному только службе каталогу квитанций. Создайте каталог с правами `0700`. Для дополнительного доверенного сертификата, если он требуется в окружении сервиса, задайте `MAX_SUPPORT_CA_FILE`. Определяйте ID по событию добавления бота в утверждённый чат. [Отправка сообщений](https://dev.max.ru/docs-api/methods/POST/messages/) · [Получение ID чата](https://dev.max.ru/docs-api/use-cases/getting-chat-id)

25 ноября 2026 года проверили в Chrome историю от выбора варианта до квитанции на синтетических данных. Тестовый получатель получил ровно один вопрос с товаром, весом и магазином. Доставка в рабочий чат требует подключения действующего бота и проверки в MAX.

В тестовой витрине обновлены сервис и виджет. Режим подготовки и копирования доступен до добавления токена и ID рабочего чата. Исходящий HTTPS к API MAX проверен с сертификатом НУЦ Минцифры, загружаемым только для клиента MAX. API вернул ожидаемый запрос авторизации. [Требования к подключению MAX](https://dev.max.ru/docs-api/)

## Подбор комплекта и корзина

Попросите «Собери заказ: рашгард и шорты размера M в Севастополе» или «Подбери экипировку для бокса». При точном выборе чат показывает варианты, цены, количества и сумму. Для неполного комплекта показывает найденные позиции и перечисляет, чего не хватает. Подбор использует опубликованный каталог витрины.

Кнопка переносит выбранные позиции в корзину текущего сеанса. MiniShop3 повторно проверяет каждую цену и доступное количество в одном магазине. При расхождении весь набор отклоняется, при повторе сохраняется выбранное количество. Покупатель проверяет результат и продолжает оформление в корзине.

На вопрос о цене чат показывает опубликованные свойства модели и розничную цену. Для размера запрашивает мерки по категории. Для одежды это рост и обхваты, для обуви — длина стопы, для боксёрских перчаток — вес и обхват кисти. Подтверждённые числовые рекомендации ограничены подходящей ростовкой каталога и проверенными сетками для отдельных моделей. [Сетка обуви Nike](https://www.nike.com/size-fit/mens-footwear) · [Сетка перчаток Fairtex](https://www.fairtex.com/pages/fairtex-size-guide) · [Материалы Fairtex BGV1](https://www.fairtex.com/products/fairtex-boxing-gloves-universal-tight-fit-design)

Для проверки Python запустите `python -B -m unittest discover -s manager-demo/web -p test_shop_dialog.py` из корня репозитория. В Chrome на изолированной витрине проверили подбор двух вещей, перенос в реальную корзину MiniShop3 и совпадение итоговой цены. В локальном PHP окружении проверили повтор, изоляцию сеансов и отклонение всего набора при расхождении цены или остатка.
