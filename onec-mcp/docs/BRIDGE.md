# COM-мост 1С через SSH

Агент в Linux получает доступ к 1С на Windows через V83.COMConnector. Этот транспорт используется, когда 1С доступна с Windows, а веб-публикации OData нет.

[К модулю 1С](../README.md) · [Файлы моста](../bridge/README.md) · [Транспорты](TRANSPORTS.md)

## Как идёт запрос

```text
Агент → node src/pipe.mjs → UNIX-сокет
      → onec-bridge-pipe.py → исходящий SSH-сеанс с Windows
      → link.mjs → onec-mcp.ps1 → V83.COMConnector → 1С
```

Мост передаёт JSON-RPC через stdin/stdout SSH-сеанса. На проверенном стенде подключение к базе занимало около 165 секунд, поэтому COM-сессия остаётся открытой. Windows-супервизор переподключается с паузой до 60 секунд. MCP-инициализация отделена от соединения с базой. После подключения транспорта `onec_status` показывает, готова ли 1С.

Менеджерский TLS-читатель остатков использует свой канал и свою служебную запись. Его восстановление описано в [инструкции по каналу менеджера](../../docs/manager-link-recovery.md).

## Подготовка

1. На Windows установите Node.js 20+ и 64-битный COMConnector. Подготовьте локальный DPAPI-файл под той же учётной записью Windows, которая запускает задачу.
2. Скопируйте [шаблон настроек](../bridge/config.example.json) в локальный `config.json`. Укажите тестовую базу, пути к учётным данным и аудиту. Для первой проверки оставьте `readonly`.
3. На Linux разместите `onec-bridge-pipe.py` в каталоге пользователя. Клиент запускает `node src/pipe.mjs`. По умолчанию прокси обращается к `~/.state/onec-bridge.sock` с правами 0600.
4. Запустите `link.mjs` на Windows и дождитесь готовности. Для запуска при входе в Windows можно использовать задачу планировщика `onec-bridge-link`.

## Инструменты и проверка

| Действие | Инструменты и поля |
| --- | --- |
| Проверить связь и метаданные | `onec_status`, `onec_metadata`, `onec_describe`, `onec_search` |
| Прочитать данные | `onec_query` с `ВЫБРАТЬ`, `onec_get`, `onec_tabular` |
| Проверить заполнение | `onec_check_fill` возвращает результат `ПроверитьЗаполнение`. Булев результат отражается в `fillCheckPassed`. |
| Подготовить запись | `onec_create` и `onec_update` с `dryRun: true` проверяют поля без вызова `Записать()`. Запись требует режима `write` или `admin`. |
| Управлять документом | `onec_post_document`, `onec_unpost_document`, `onec_mark_delete`. `postingReady` в `onec_status` показывает доступность системного перечисления режимов записи. |
| Удалить объект | `onec_delete` доступен в `admin`. |

Журнал JSONL может содержать аргументы вызова. Храните его в локальном каталоге с ограниченным доступом. Правила `allow` и `deny` ограничивают доступные объекты дополнительно к правам в 1С.

Ранний прогон подтвердил чтение метаданных и полей, запрос с возвратом ссылок, `dryRun` и цикл создания, правки и удаления отдельного тестового элемента. Проведение документов на стенде остаётся отдельной проверкой.

## Диагностика

```bash
test -S ~/.state/onec-bridge.sock
pgrep -f onec-bridge-pipe
```

Если сокета нет, проверьте подключение Windows и локальный журнал `link.err.log`. Если сокет есть, отправьте `onec_status` и проверьте права пользователя 1С, регистрацию COMConnector и журнал аудита. После перезагрузки Linux сокет появится при следующем подключении Windows.
